Frontend Integration Guide — Add Service (Proposal Services)
The "Add Service" feature is part of the proposal flow, not the settings page. Services are additional items (e.g. luggage transfer, disabled access, air conditioning, extra beds, bar service) added to a proposal.

Base URL
All endpoints: /api/v1/proposals/:proposalId/services
Auth: Authorization: Bearer <token> (all roles — admin and staff)

1. Add Service
POST /api/v1/proposals/:proposalId/services

Figma screen: The "Add Service" modal with free-text name OR a list of predefined services to pick from.

Request body:


{
  "serviceName": "Luggage transfer",
  "dateFrom": "2026-04-01",
  "dateTo": "2026-04-07",
  "buyPrice": 50,
  "sellPrice": 75,
  "markupPercent": 18,
  "quantity": 10,
  "days": 6,
  "notes": "Transfer from airport to hotel"
}
Field	Type	Required	Notes
serviceName	string	Yes	The service name — free text or from predefined list
dateFrom	string (ISO date)	No	Start date e.g. "2026-04-01"
dateTo	string (ISO date)	No	End date e.g. "2026-04-07"
buyPrice	number	No	Buying/cost price (internal)
sellPrice	number	No	Selling price shown to customer
quantity	number (integer)	No	Number of units
days	number (integer)	No	Number of days
notes	string	No	Internal notes, max 2000 chars
Success Response (200):


{
  "success": true,
  "data": {
    "proposal": { ...updated proposal object... },
    "service": {
      "id": "uuid",
      "proposalId": "uuid",
      "serviceName": "Luggage transfer",
      "dateFrom": "2026-04-01T00:00:00.000Z",
      "dateTo": "2026-04-07T00:00:00.000Z",
      "buyPrice": "50.00",
      "sellPrice": "75.00",
      "quantity": 10,
      "days": 6,
      "notes": "Transfer from airport to hotel",
      "createdAt": "2026-03-27T10:00:00.000Z"
    }
  },
  "message": "Service added"
}
2. Update Service
PATCH /api/v1/proposals/:proposalId/services/:serviceId

All fields are optional — only send what changed.

Request body:


{
  "sellPrice": 80,
  "quantity": 12
}
Response: Same shape as Add Service.

3. Remove Service
DELETE /api/v1/proposals/:proposalId/services/:serviceId

No body needed.

Success Response (200):


{
  "success": true,
  "data": { ...updated proposal object... },
  "message": "Service removed"
}
Figma Screen 1 — Free Text Mode
The first Figma screen shows a form with:

SERVICE NAME → serviceName (free text input)
DATE FROM / DATE TO → dateFrom / dateTo
BUY PRICE (€) → buyPrice
SELL PRICE (€) → sellPrice
MARKUP (%) → calculate sellPrice from buyPrice on the frontend: sellPrice = buyPrice * (1 + markup/100) — only send buyPrice and sellPrice in the request, no markupPercent field
QUANTITY → quantity
NIGHT → days
Figma Screen 2 — Predefined List Mode
The second screen shows a list of predefined services to pick from:

Luggage fees
Disabled access
Air conditioning
Extra available
Bar
These are just preset values for serviceName — the frontend renders them as checkboxes or quick-select options. When selected, they populate the serviceName field. The API call is the same — you still POST with the selected name.

Summary Table
Method	Endpoint	Purpose
POST	/api/v1/proposals/:proposalId/services	Add a service to a proposal
PATCH	/api/v1/proposals/:proposalId/services/:serviceId	Update an existing service
DELETE	/api/v1/proposals/:proposalId/services/:serviceId	Remove a service
The proposalId comes from the proposal you're currently viewing/editing.
