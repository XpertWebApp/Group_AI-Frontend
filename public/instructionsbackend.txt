2. Authentication
You already have login/logout. Here's the full reference:

POST /api/v1/auth/login

// Request body
{ "email": "user@example.com", "password": "secret", "rememberMe": true }

// Response data
{ "accessToken": "jwt...", "refreshToken": "rt...", "user": { "id", "email", "name", "role" } }
POST /api/v1/auth/refresh

// Request body
{ "refreshToken": "rt..." }

// Response data
{ "accessToken": "new-jwt...", "refreshToken": "new-rt..." }
POST /api/v1/auth/logout
No body needed.

Auth Header for ALL Protected Endpoints

Authorization: Bearer <accessToken>
Every endpoint below (except /hotels/image) requires this header. If missing or expired, you'll get a 401.

Tip: Set up an Axios/fetch interceptor that:

Adds Authorization: Bearer <token> to every request
On 401, tries POST /auth/refresh automatically, then retries the original request
On refresh failure, redirects to login

8. Hotel Search Flow (the core feature)
This is the most complex part. Here's the step-by-step flow:

Step 1: Trigger Hotel Search
POST /api/v1/requests/:id/hotel-search

// Request body (all optional)
{
  "mealType": "BB",                  // "BB"|"RO"|"HB"|"FB"|"AI" — filter by meal
  "includeAlternativeStars": true,   // search ±1 star ratings too
  "waitSeconds": 35,                 // 5-60, how long to wait for WBE
  "currencyCode": "EUR",            // override
  "nationalityCode": "DE"           // override
}
Response:


{
  "success": true,
  "data": {
    "requestId": "uuid",
    "totalCandidates": 45,
    "jobsQueued": 45,
    "message": "Hotel search started — 45 candidate hotels queued for probing",
    "sseEndpoint": "/api/v1/requests/{id}/hotel-search/events",
    "statusEndpoint": "/api/v1/requests/{id}/hotel-search/status"
  }
}
Important: The search is asynchronous. The response just confirms jobs were queued. You need to either use SSE or polling to get results.

Step 2A: Real-Time Updates via SSE (recommended)
Connect to GET /api/v1/requests/:id/hotel-search/events using EventSource:


const eventSource = new EventSource(
  `${API_BASE_URL}/requests/${requestId}/hotel-search/events`,
  { 
    headers: { 'Authorization': `Bearer ${token}` }
    // Note: native EventSource doesn't support headers.
    // Use a library like 'eventsource' or 'event-source-polyfill'
    // OR pass token as query param if backend supports it
  }
);

// Initial connection confirmed
eventSource.addEventListener('connected', (e) => {
  console.log('SSE connected', JSON.parse(e.data));
});

// Each hotel probe completes one by one
eventSource.addEventListener('hotelProbeProgress', (e) => {
  const data = JSON.parse(e.data);
  // data = { jobId, hotelCode, hotelName, status, result: HotelResult | null }
  // Update progress bar: completed / total
});

// All probes done
eventSource.addEventListener('hotelProbeCompleted', (e) => {
  const data = JSON.parse(e.data);
  // data = { requestId, summary: { total, completed, failed, skipped } }
  eventSource.close();
});

eventSource.onerror = () => {
  // Fall back to polling
  eventSource.close();
};
Step 2B: Polling Fallback
GET /api/v1/requests/:id/hotel-search/status

// Response data
{
  "requestId": "uuid",
  "summary": {
    "total": 45,
    "queued": 10,
    "running": 5,
    "completed": 25,
    "skipped": 3,
    "failed": 2
  },
  "jobs": [
    {
      "id": "uuid",
      "hotelCode": "HTL123",
      "hotelName": "Grand Hotel",
      "status": "COMPLETED",  // QUEUED | RUNNING | PROBING | COMPLETED | SKIPPED_INSUFFICIENT | FAILED
      "result": { /* HotelResult object — see below */ }
    }
  ]
}
Poll every 3-5 seconds until summary.queued + summary.running === 0.

Display Logic:

status === "include" → show as primary result (green)
status === "flag" → show with warning icon (yellow) — inventory overlap risk
status === "omit" → hide from customer view, show only in agent dashboard
inventoryOverlapFlag === true → show "Unverified inventory" warning
